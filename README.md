# Coding Agent A/B 快照仓库

保存每道题的初始代码及 A/B 首轮运行产物，供复现与核验使用。

## 仓库组织

- `main`：仓库说明与记录模板，不代表任何题目的初始环境。
- `codex/task-001-base`：第 001 题模型运行前的初始环境。
- `codex/task-001-a`：从初始提交开始的 A 运行及最终产物。
- `codex/task-001-b`：从同一个初始提交开始的 B 运行及最终产物。
- 其他题目使用不同题号。不同项目可使用独立提交历史；不要把上一题的产物误作下一题起点。

## 每题流程

1. 准备项目、依赖、提示词和验收标准，检查敏感信息与忽略规则。
2. 保存初始提交并推送 base 分支，记录 40 位完整 SHA。
3. 在运行前复制配置好的工作区，保留 Git 历史；处理虚拟环境和缓存的绝对路径。
4. A/B 分别建立对应分支，确认两边 `git rev-parse HEAD` 都是初始 SHA。
5. 使用相同提示词、Harness、版本、机器和配置，各运行首轮。
6. 分别保存并推送最终产物。已有模型提交应保留，不 squash、不改写历史；工作区干净时无需额外提交。
7. 填写初始、A、B 三条 commit 永久链接。录屏及轨迹按项目要求单独保存。

链接格式：

```text
https://github.com/LiMing0016/coding-agent-snapshots/commit/<40位完整SHA>
```

## 核验

在包含 A/B 提交的本地仓库中运行（替换占位符）：

```powershell
git merge-base --is-ancestor <初始SHA> <A最终SHA>
$LASTEXITCODE
git merge-base --is-ancestor <初始SHA> <B最终SHA>
$LASTEXITCODE
```

两次退出码均应为 0；还需确认两次确实从初始环境开始，祖先关系本身不能证明环境完全一致。

## 保存与访问

- 仓库公开，任何人都可通过链接查看代码与提交历史；仅上传允许公开的题目代码和资料。
- 不提交 API Key、真实 `.env`、凭据、连接串、个人数据、轨迹或录屏。
- 保留需要复现的源代码、配置模板、依赖锁文件及必要测试资源。
- 依赖、缓存、构建产物一般不入库；Git 快照不等于完整运行环境备份。
- 不对已交付提交做 force-push、rebase 或 squash，保留对应远端分支。
- 记录模板见 `templates/task-record.md`。复制到本地填写，提交到远端前检查内容与访问权限。

当前仅完成仓库初始化，尚未包含任何题目的实际代码快照。
